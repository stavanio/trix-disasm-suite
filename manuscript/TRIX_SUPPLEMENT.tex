\section{Admissibility definitions and scope}

The revised theoretical analysis does not require the nominal controller
stability and bounded-neural-error assumptions used by the submitted ISS
argument. Instead, the following definitions specify the conditions under
which the command-level governor is interpreted.

\paragraph{Declared task context.}
The admissible action set is written as
$\mathcal{A}(x,c)$, where $x$ denotes the observed physical state and $c$
denotes task context such as primitive identity, phase, or task-frame
orientation. Any result involving context-conditioned admissibility assumes
that the corresponding context variable is supplied to the governor. The implemented context-limited runtime arms are identified by the
observation fields used to construct their bounds. In the benchmark
harness, sharing the same task observation does not require every arm to
condition on every field; the concrete field use is specified in
Supplementary Section~S4.

\paragraph{Projection well-posedness.}
Whenever TRiX returns a projected command, the corresponding admissible set is
required to be nonempty and closed so that a Euclidean minimizer exists. When
the set used in an experiment is convex, the minimizer is unique. For
non-projectable symbolic violations, the runtime outcome is REJECT rather than
an implicit projection onto an undefined set.

\paragraph{Specification validity.}
Membership in $\mathcal{A}(x,c)$ means satisfaction of the \emph{modeled}
command-level constraint. It does not prove that the specified threshold,
margin, coordinate transform, or physical model is correct. Specification
validity is therefore evaluated separately from solver correctness. This
distinction is central to the BATTERY matched-specification experiment and the
PCB margin audit in the revised study.

\paragraph{Execution scope.}
The analytical results concern command admissibility and representation. They
do not establish closed-loop stability, forward invariance of an unmodeled
plant, or robustness to arbitrary state-estimation, tracking, perception, or
contact-model error. Those effects are outside the theorem-level claims of the
revised manuscript.


\section{Reference Projection Operators}

This Supplementary section records the analytical operators used in the revised benchmark.
The revised framework is expressed in terms of admissible action sets rather
than assuming that every task constraint is an equality manifold.


\subsection{Helical Projection (SCREW)}

SCREW v3 uses normalized command
$a=(a_v,a_\omega,a_r)$, with
$v_z^c=S_v a_v$, $\omega_z^c=S_\omega a_\omega$ and
$F_r^c=S_r a_r$. The constants are
$S_v=0.05$ m\,s$^{-1}$, $S_\omega=60$ rad\,s$^{-1}$,
$S_r=40$ N, $p=1.25$ mm, $k=p/(2\pi)$ and
$\epsilon=0.001$ m\,s$^{-1}$. The implemented command set is
\[
\mathcal A_{\rm screw}=
\left\{a:
\begin{array}{l}
|S_v a_v-kS_\omega a_\omega|\leq\epsilon-\eta,\\
|a_v|\leq1,\quad |a_\omega|\leq1,\quad |a_r|\leq r_{\rm int}
\end{array}\right\},
\]
where $\eta=10^{-6}\epsilon$ is the numerical interior offset and
$r_{\rm int}$ is the radial bound after the recorded stochastic margin.

The axial--angular slice is a convex polygon obtained by clipping the command
square with the two helical halfspaces. An admissible proposal is unchanged;
otherwise the analytical implementation selects the nearest point on the
polygon's edges. Radial action is clipped independently. The objective is
Euclidean distance in normalized action coordinates.

The matched QP minimizes that same objective over these same inequalities.
The zero-tolerance line projection in the main text illustrates the coupling;
it is not the finite-slab operator used in the experiments. Equal task-level
SCREW results do not by themselves certify pointwise numerical equality.


\subsection{Disk--Interval Projection (PCB)}

PCB v2 uses normalized action

\[
a=
\begin{bmatrix}
a_x & a_y & a_z
\end{bmatrix}^{\top},
\]

where the first two components command tilt torque and the third commands lift.
Let $r_\tau$ denote the declared tilt radius in normalized action units and let
$[\ell_z,r_z]$ denote the allowed lift interval. The admissible set is

\[
\mathcal{A}_{\mathrm{PCB}}
=
\left\{
a:
a_x^2+a_y^2\leq r_\tau^2,
\;
\ell_z\leq a_z\leq r_z
\right\}.
\]

Writing

\[
\rho=\sqrt{a_x^2+a_y^2},
\]

the exact Euclidean projection of the tilt pair is

\[
(a_x',a_y')
=
\begin{cases}
(a_x,a_y), & \rho\leq r_\tau,\\[4pt]
\dfrac{r_\tau}{\rho}(a_x,a_y), & \rho>r_\tau,
\end{cases}
\]

and the lift component is

\[
a_z'=\min\{r_z,\max\{\ell_z,a_z\}\}.
\]

Thus the revised PCB operator projects onto a disk crossed with an interval.
It does \emph{not} zero both tilt torques, and it is not the six-dimensional
wrench operator described in the submitted appendix.

The physical nominal planarity limit is
$\tau_{\max}=0.100\,\mathrm{N\,m}$. Where chance tightening is enabled, the
runtime radius is derived separately from the margin policy rather than being
silently substituted for the physical threshold.


\subsection{BATTERY Specification and Runtime Operators}

The submitted appendix represented BATTERY as projection onto the instantaneous
half-space $F\cdot v\leq P_{\max}(T)$. That expression is not used as the
sole enforcement model in BATTERY v2.

The revised task distinguishes preventive deformation limits, modeled damage
onset, internal short, and subsequent thermal evolution. Runtime comparisons
therefore identify both the \emph{constraint specification} and the
\emph{operator form}. In particular, the matched-specification experiment
compares componentwise and TRiX operators using the same 15-N preventive
threshold. The submitted comparison that mixed a 20-N damage threshold with a
different projection geometry is retained only as provenance and is not used
to infer representational superiority.

The executable definitions of the BATTERY operators are fingerprinted with the
benchmark registry and margin policy. Because the scientific comparison
depends on specification as well as projection form, we do not replace those
definitions here with a second informal analytical approximation.


\subsection{Phase- and Frame-Conditioned Operators}

SNAP and CRANK use task-conditioned admissible sets. In SNAP, the applicable
pull authority depends on latch state and manipulation phase. In CRANK, the
transverse admissible set additionally depends on task-frame orientation.

These operators are evaluated specifically as context-conditioned runtime
governors. Their purpose is not to establish that curved geometry is generally
superior to clipping; the experiments test whether the information and action
authority required by the task are available to the governor.


\subsection{PRY Restriction}

PRY provides a control case in which a simpler restriction can retain the
task-relevant authority. The separate fixed-budget control compares the
implemented static and insertion-dependent restrictions. Similar observed
completion rates do not establish equivalence or a geometric causal effect;
the reported outcome is scoped to those policies and configurations.


\section{Supplementary proofs for representation propositions}

This Supplementary section consolidates the representation results stated in main Section~2.1.
They characterize properties of admissible action sets and do not constitute a
closed-loop stability theorem.

\Needspace{8\baselineskip}
\subsection*{Proposition 1: separable sets reduce to componentwise clipping}

Let

\[
\mathcal{B}
=
\prod_{i=1}^{m}[\ell_i,r_i]
\]

and consider the Euclidean projection

\[
\Pi_{\mathcal{B}}(\tilde u)
=
\arg\min_{u\in\mathcal{B}}
\frac{1}{2}\sum_{i=1}^{m}(u_i-\tilde u_i)^2 .
\]

Because both the objective and feasible set separate by coordinate, the
optimization decomposes into $m$ scalar problems,

\[
u_i^\star
=
\arg\min_{\ell_i\leq u_i\leq r_i}
\frac{1}{2}(u_i-\tilde u_i)^2 .
\]

Each scalar minimizer is

\[
u_i^\star
=
\min\{r_i,\max\{\ell_i,\tilde u_i\}\},
\]

which is exactly componentwise clipping. Therefore an exact Euclidean
projector has no representational advantage over clipping when both methods
enforce the same axis-aligned product set with the same margins.

This result does not apply when the admissible set contains coupled
coordinates, state dependence, phase dependence, or a different physical
margin.


\Needspace{8\baselineskip}
\subsection*{Proposition 2: consequence of phase blindness}

Let $\mathcal{A}_1$ and $\mathcal{A}_2$ denote the admissible sets in two task
phases and let $\mathcal{B}$ be a single phase-independent restriction.

For $\mathcal{B}$ to be admissible in phase 1,

\[
\mathcal{B}\subseteq\mathcal{A}_1,
\]

and for it to be admissible in phase 2,

\[
\mathcal{B}\subseteq\mathcal{A}_2.
\]

Hence

\[
\mathcal{B}
\subseteq
\mathcal{A}_1\cap\mathcal{A}_2 .
\]

If $\mathcal{A}_1\neq\mathcal{A}_2$, their intersection is a strict subset of
at least one phase-specific set. Thus any restriction that is safe in both
phases necessarily removes some phase-specific admissible authority from at
least one phase. Conversely, if a phase-independent restriction admits an
action outside the intersection, that action is inadmissible in at least one
phase.

The proposition establishes a representation/information limitation only. It
does not establish that the removed actions are required for successful task
completion. Whether the lost authority is task-essential is determined
empirically.


\Needspace{8\baselineskip}
\subsection*{Proposition 3: conservatism under unknown rotation}

Let

\[
\mathcal{R}_0
=
\{u\in\mathbb{R}^{2}:
|u_1|\leq a,\;
|u_2|\leq b\},
\qquad
a\geq b>0,
\]

and let

\[
\mathcal{R}_{\theta}
=
R(\theta)\mathcal{R}_0 .
\]

First consider any $u$ satisfying $\lVert u\rVert_2\leq b$. Rotation preserves
Euclidean norm, so in every rotated coordinate system each component has
magnitude at most $\lVert u\rVert_2\leq b\leq a$. Hence

\[
u\in\mathcal{R}_{\theta}
\quad
\text{for every }\theta.
\]

Therefore the radius-$b$ disk is contained in
$\bigcap_{\theta}\mathcal{R}_{\theta}$.

Now let $\lVert u\rVert_2>b$. Choose an orientation for which the narrow axis
of the rectangle is aligned with $u$. In that orientation, the narrow-axis
coordinate of $u$ has magnitude $\lVert u\rVert_2>b$, so

\[
u\notin\mathcal{R}_{\theta}.
\]

Therefore

\[
\bigcap_{\theta}\mathcal{R}_{\theta}
=
\{u:\lVert u\rVert_2\leq b\}.
\]

For a symmetric fixed world-frame box $[-h,h]^2$, the corner
$(h,h)$ has norm $\sqrt{2}h$. Requiring every point in the box to remain
inside the radius-$b$ disk gives

\[
\sqrt{2}h\leq b,
\]

and hence

\[
h\leq\frac{b}{\sqrt{2}}.
\]

This is a worst-case orientation result. The CRANK experiment exercises
angle-conditioned task-frame constraints, but is not interpreted as an
experimental isolation of rotation alone.


\Needspace{8\baselineskip}
\subsection*{Proposition 4: feasibility of probabilistic tightening}

Let the nominal scalar physical limit be

\[
|y|\leq L,
\qquad
L>0,
\]

and let uncertainty have standard deviation $\sigma>0$. For a declared
Gaussian quantile $z>0$, the tightening margin is

\[
m=z\sigma.
\]

The tightened admissible interval is

\[
|y|\leq L-z\sigma.
\]

Its radius is therefore

\[
r=L-z\sigma.
\]

Three cases follow directly:

\begin{enumerate}
\item If $z\sigma<L$, then $r>0$ and the tightened set contains nonzero
      admissible commands.
\item If $z\sigma=L$, then $r=0$ and the only admissible command is $y=0$.
\item If $z\sigma>L$, then $r<0$ and the tightened interval is empty.
\end{enumerate}

Thus nonzero command authority exists if and only if

\[
z<\frac{L}{\sigma}.
\]

This result separates probabilistic-margin feasibility from the behavior of
the projection algorithm. A projection mechanism cannot recover authority
that has been eliminated by the declared margin.


\subsection*{Affine projection and quadratic-program equivalence}

For completeness, consider the affine constraint

\[
Au=b
\]

with full-row-rank $A$. The Euclidean projection problem

\[
\min_u
\frac{1}{2}\lVert u-\tilde u\rVert_2^2
\quad
\text{subject to}
\quad
Au=b
\]

has Lagrangian

\[
\mathcal{L}(u,\lambda)
=
\frac{1}{2}\lVert u-\tilde u\rVert_2^2
+
\lambda^\top(Au-b).
\]

Stationarity gives

\[
u-\tilde u+A^\top\lambda=0,
\]

so

\[
u=\tilde u-A^\top\lambda.
\]

Substitution into the equality constraint yields

\[
AA^\top\lambda=A\tilde u-b,
\]

and therefore

\[
u^\star
=
\tilde u
-
A^\top(AA^\top)^{-1}(A\tilde u-b).
\]

Accordingly, a closed-form implementation and a quadratic-program solver
provided with the same affine constraint solve the same mathematical
optimization problem. The revised SCREW solver comparison tests numerical
agreement and computational cost, not representational superiority.


\subsection*{Policy adaptation}

No proposition in this Supplementary section states that training can or cannot overcome a
particular runtime restriction. Filter-aware training changes the policy's
proposal distribution and may allow the policy to adapt to retained action
authority. Whether that adaptation succeeds is task dependent and is therefore
reported only as an empirical result in main Results.

\subsection{Reward and Progress Contract}

The revised environments use task-specific rewards rather than relying on the
single reconstructed reward equation from the submitted PDF. Each environment
records a normalized task-progress quantity used by the frozen checkpoint
selection rule:

\begin{itemize}
\item SCREW: axial extraction progress;
\item PCB: lift progress;
\item SNAP: extraction progress;
\item CRANK: rotation progress;
\item BATTERY: peel progress; and
\item PRY: gap-opening progress.
\end{itemize}

Safe completion is ranked before progress during checkpoint selection so that a
do-nothing policy cannot win merely by avoiding damage. Reward values affect
policy learning, whereas the five-category episode outcome contract is computed
independently for evaluation.

The taxonomy separates the role of a measured constraint from the physical
mechanism that generated it. Outcome-affecting families enter the five-category
episode contract, whereas diagnostic families remain visible without changing
an intact completion by themselves. An unclassified family defaults to
outcome-affecting so that adding a new constraint cannot silently remove it
from evaluation.

One frozen naming mismatch is retained for provenance. The SNAP environment
emits \texttt{vio\_premature}, whereas the explicit taxonomy entry is named
\texttt{vio\_premature\_pull}. Because unlisted violation families inherit the
outcome-affecting default, the emitted family has the intended classification.
We preserve the historical taxonomy hash rather than silently changing the
declaration after the production runs.


\subsection{Chance-Constraint Margins}

Where stochastic tightening is used, the margin is derived from an
episode-level risk target and the applicable episode horizon. With Gaussian
noise this is a chance constraint under the assumed distribution, not a
deterministic robustness guarantee.

The implementation records separately whether a tightened set is

\begin{enumerate}
\item nonempty,
\item nonempty with positive nonzero command authority, or
\item infeasible.
\end{enumerate}

This distinction is required because the singleton set containing only the zero
command is mathematically nonempty while still providing no nonzero authority
for task progress.

\section{Training Configuration}
\subsection{Learning Implementation}

Only two trained policy algorithms are reported: Proximal Policy Optimization
(PPO) \cite{ref31} and Soft Actor-Critic (SAC) \cite{ref32}. Policies are
trained with Stable-Baselines3 v2.9.0 and Gymnasium v1.3.0 using a two-layer
MLP with hidden widths $[256,256]$. The earlier custom SAC implementation was
retired before the reported experiments, and none of its results are retained.

The Gymnasium adapter distinguishes true environment termination from
time-limit truncation. Evaluation also saves and restores NumPy random state so
that interleaved evaluation cannot alter subsequent training.

When a runtime restriction is active during training, the policy action is
interpreted as a \emph{nominal} command and the restriction is part of the
environment transition:

\[
a_{\mathrm{nominal}}
\longrightarrow
\text{governor}
\longrightarrow
a_{\mathrm{executed}}
\longrightarrow
\text{plant}.
\]

The replay or rollout buffer therefore contains the policy's nominal action,
not an assertion that the policy itself emitted the corrected command. We
refer to this explicitly as the \emph{filter-as-environment} MDP framing.


\subsection{Two Evaluation Modes}

The revision separates two questions that the submitted evaluation conflated.

\paragraph{Stage 1: frozen-policy governance.}
For each task, algorithm, and training seed, a nominal PPO or SAC policy is
trained without the evaluated runtime arm. After checkpoint selection, the
same frozen policy is evaluated through each applicable arm on the same
held-out episode seeds. Thus the arms receive proposals from the same learned
policy, and the comparison asks how well each mechanism governs a policy it did
not train.

\paragraph{Stage 2: filter-aware training.}
A second set of policies is trained with the corresponding restriction active
inside the environment transition. This asks whether the learned policy can
adapt its nominal proposal distribution to the authority retained by a
restriction. Stage~1 and Stage~2 are reported separately; one is not used as a
surrogate for the other.


\subsection{Frozen Checkpoint Selection and Held-Out Evaluation}

Checkpoint selection is fixed before the reported held-out evaluations.
For every task--algorithm--training-seed cell:

\begin{enumerate}
\item train to the predeclared task budget and save a checkpoint every
      1000 training steps;
\item evaluate every checkpoint on 30 fixed validation episodes;
\item rank contiguous three-checkpoint windows by mean safe-completion rate
      and retain the center checkpoints of the three best windows;
\item re-evaluate those candidates on 70 additional validation episodes,
      producing 100 validation episodes per candidate;
\item select lexicographically by maximum safe completion, minimum destructive
      completion, maximum normalized progress, minimum episode-level violation
      incidence, and then earliest checkpoint;
\item evaluate the selected checkpoint once on 100 held-out test episodes; and
\item repeat for ten production training seeds, $0,\ldots,9$.
\end{enumerate}

Validation and held-out test episodes are disjoint. Pilot seeds used during
pipeline development are excluded from reported results. The candidate
checkpoint set and ranking rule are part of the frozen protocol rather than
post-hoc analyst choices.

The current seed scheduler uses explicit deterministic task offsets, with a
deterministic digest fallback for future task names, rather than Python's
process-dependent \texttt{hash()} function. Historical artifacts were audited
for seed pairing; any identified mismatch is preserved in provenance and
corrected transparently rather than silently overwritten.

\subsection{Constraint Margins and Specification Controls}

For constraint families requiring stochastic tightening, the margin is derived
from a declared episode-level risk budget and episode horizon, with allocation
across applicable constraint families. Gaussian tightening is therefore
described as a chance constraint under the assumed noise model, not as a
worst-case robustness guarantee.

The implementation distinguishes three feasibility states:

\begin{itemize}
\item the tightened set is nonempty;
\item the tightened set retains positive nonzero action authority; or
\item the tightened set is infeasible.
\end{itemize}

Specification is evaluated independently of projection form. Two explicit
controls are important in the revised study. First, BATTERY includes a
matched-specification comparison in which componentwise and TRiX arms enforce
the same preventive force threshold. Second, PCB results retain the provenance
fact that the historical box and TRiX arms differed both in set form and in
effective margin; that comparison is therefore not used as an isolated proof
of geometric superiority.


\subsection{Reproducibility and Provenance}

An implementation audit identified a distinction between the later per-family
margin-policy registry and the values used by several archived executable
filters. Historical PCB, SNAP, CRANK, BATTERY, and PRY filters used the common
default tightening when no explicit multiplier was supplied, while the SCREW
radial restriction used its independently derived task value. Historical runs
are therefore reported as executed and are not regenerated under the later
registry. The registry is treated as declarative specification metadata rather
than as a complete executable fingerprint for these archived runs. Pairwise
comparisons remain margin-matched where both arms use the same bound
construction; PCB and SNAP are interpreted as implemented-governor comparisons
because their compared arms also differ in margin specification.


Every quantitative run records the task constraint fingerprint, margin-policy
hash, outcome-taxonomy hash, and protocol-freeze hash together with execution
mode, evaluated arm, policy algorithm, training seed, selected checkpoint, and
episode seeds. Records with missing or mismatched provenance fields are not
pooled.

The registry is the single binding between environment versions and runtime
arms. The deterministic seed schedule, historical seed audit, specification
and margin audits, and interpretation limits are recorded in
\texttt{docs/provenance.md}. Frozen historical artifacts are retained rather
than rewritten after an audit correction.

The reported training implementation uses Stable-Baselines3 rather than the
retired custom agents. PPO and SAC are the only trained policy algorithms
claimed in the revised paper. Analytical, learned-constraint, oracle, and
matched QP arms are identified by their actual role rather than described as
trained policies.

Protocol hashes are retained as historical identifiers rather than rewritten
when the protocol record is later amended. The original Stage~1 production

\section{Implementation and Specification Validation}

The revised validation separates implementation agreement from independent
physical validation.

\paragraph{Implementation consistency.}
Environment acceptance tests verify declared state transitions, outcome
families, progress metrics, constraint fingerprints, and filter behavior.
Agreement between code and the equations used to construct that same
environment establishes implementation consistency only.

\paragraph{Matched solver specification.}
The analytical, active-set QP and operator-splitting implementations in
\texttt{baselines/screw\_solvers.py} use the same normalized SCREW command
polytope. The policy results establish matching task-level outcomes for the
registered analytical and matched-QP arms. The new saved input-bank checks
in Supplementary Section~S8 measure pointwise agreement of the scalar and NumPy analytical
projectors, active-set QP and reused OSQP. The observed errors apply to that
declared workload, rather than constituting a universal numerical error bound.

\paragraph{Specification sensitivity.}
The archived sweep contains 21 constants at five multipliers, with eight
scripted episodes per arm and case. It records 96 passing and nine failed
task-specific orderings. The failures comprise six PCB boundary/model
inconsistencies, one CRANK tightened-set failure, and two BATTERY cases with
zero destructive completions but lower safe completion for the designated
preventive arm. These are post-hoc diagnoses of the observed sweep, not a
96/96 certification conditional on two sufficient safety preconditions.

\subsection{Specification failure: exact projection cannot repair the wrong boundary}

Projection correctness and specification correctness are independent.

BATTERY provides the clearest task-level example: enforcing the 20-N flagged
damage threshold and enforcing the 15-N preventive deformation threshold are
different physical specifications. Changing projection geometry cannot make
the former equivalent to the latter.

The sensitivity archive records the expected task-specific ordering in
96 of 105 perturbation cases. Six failed PCB cases reduce stiffness or yield
curvature, or increase the tilt-torque limit, so the permitted torque is
inconsistent with the modeled yield boundary. One failed CRANK case halves
the axial limit, leaving no feasible command under the declared tightening.
The remaining two failures are different: at BATTERY deformation onsets of
22.5 and 30 N, both compared arms have zero destructive completions, but the
designated preventive arm has lower safe completion (12.5\% and 0.0\% versus
100.0\%). They fail the sweep's ordering criterion without recorded damage.

This is a post-hoc description of six PCB, one CRANK and two BATTERY
exceptions. It does not support the earlier claim that all nine failures
were violations of two safety preconditions, or a 96/96 safety guarantee
within a retrospectively defined valid region.



\section{Recorded Computational Cost}
\label{sec:si-runtime}

We measured the complete implemented filter call,
$(o,a)\mapsto(a',\mathrm{info})$, for all 20 registered non-passthrough arms
across the six tasks, plus the NumPy SCREW polygon projector and reused OSQP.
The measurement includes array conversion and allocation, per-call constraint
construction, projection and diagnostic construction. Input generation,
imports, policy or VLM inference, simulator steps, output validation and robot
communication are outside the timer. This new benchmark replaces the
unsupported historical timing figures; it does not reconstruct their provenance.

\paragraph{Workload and repetition.}
Each task has 2,048 saved float32 observation/action pairs generated with seed
20260925. Half the actions are uniform in $[-1,1]^3$, one quarter scales the
TRiX projection by a factor in $[0.1,0.9]$, and one quarter perturbs that
projection toward the original proposal by $10^{-4}$ normalized units before
clipping to the action cube. These deliberately constructed strata exercise
different correction costs; their weights are not policy visitation frequencies.
Observations come from the existing environment encoders: reset states for
state-independent filters, equal engaged/disengaged SNAP cases, CRANK angles
before and after its rotation threshold, and PRY insertion depths over its
declared range. No environment rollout or policy retraining is involved.

Five fresh Python processes each warm every callable for 256 calls, then time
all 2,048 inputs per implementation, giving 10,240 recorded calls per row and
225,280 calls overall. Each process uses a seeded input permutation and
randomizes task and implementation order within 64-input blocks. The arms for
each task receive the same input sequence. Cyclic garbage collection is
disabled during the timing loop; ordinary allocation and reference counting
remain included. Durations use \texttt{perf\_counter\_ns}. All samples,
including outliers, are retained. The empty timer-pair median is 0.025~$\mu$s
and is not subtracted. Table~\ref{tab:runtime-latency} reports pooled medians,
95th percentiles and the range of the five process medians. Raw per-call
durations, outputs, failure flags, call order, strata and maxima are preserved.

\paragraph{Host and solver settings.}
The measurements used an Intel Core Ultra 9 275HX under Linux 7.0.0-31,
CPython 3.12.3, NumPy 1.26.4, SciPy 1.11.4, quadprog 0.1.13 and OSQP 1.1.3.
Each worker was pinned to CPU~0, native numerical thread limits were set to
one, and the recorded process thread count was one. The existing
\texttt{intel\_pstate} powersave policy and frequency scaling were retained.
OSQP reuses its problem object and warm start; both absolute and relative
tolerances are $10^{-9}$, the iteration cap is 20,000, and polishing is enabled
with zero refinement iterations. Object construction took 0.662--0.674~ms
across the five processes and is excluded from steady-state call times.
Active-set QP retains its existing per-call matrix construction. Solver
diagnostic work remains inside the timed call; worker output is redirected to
saved logs. These choices measure the supplied implementations as used, with
setup reuse explicitly stated.

\paragraph{Matched comparison and scope.}
For the same SCREW command polytope and inputs, the production scalar TRiX
projector has median/95th-percentile latency 1.255/1.556~$\mu$s, compared with
12.578/15.534~$\mu$s for active-set QP and 14.924/19.895~$\mu$s for reused OSQP.
The scalar, NumPy and active-set outputs coincide in float32 on this bank;
the largest absolute action-coordinate difference from OSQP is
$1.013\times10^{-6}$. All four implementations pass the predeclared
$10^{-5}$ action-agreement and $10^{-7}$ constraint-residual tolerances with
zero recovery outputs. These are checks on the saved bank, not a proof for
arbitrary inputs. The alternative NumPy analytical projector takes
18.16/20.90~$\mu$s, demonstrating that allocation and implementation choices
materially affect the comparison even for the same projection geometry.

Across the six registered TRiX arms, median latency ranges from 1.12 to
11.77~$\mu$s; BATTERY's preventive variant takes 3.12~$\mu$s. The
componentwise and oracle-tangent controls on the other tasks implement
different restrictions, so their times are descriptive overhead comparisons
without a claim of equivalent safety. CRANK's TRiX median exceeds its static
clip median, for example, while including frame-dependent projection and
tightening diagnostics. The largest recorded call is 352.56~$\mu$s for OSQP;
the largest registered TRiX call is 335.81~$\mu$s for CRANK. A single-host
distribution does not establish worst-case execution time or an end-to-end
real-time guarantee.

\subsection{SNAP: phase-conditioned robust governance versus a static baseline}

On SNAP, filter-aware SAC achieves 5.2\% safe completion with the simpler
restriction and 96.5\% with the task-conditioned governor.

For SNAP, this is an implemented-governor comparison rather than a
phase-only or geometry-only ablation. The static arm is phase-blind and uses
nominal bounds, whereas the TRiX arm is phase-conditioned and uses the archived
robust tightening. The observed gap therefore supports the combined governor
configuration but does not isolate phase information or tightening as the sole
cause.

This comparison should not be interpreted as evidence that curved geometry is
responsible for the difference. The phase-conditioned SNAP admissible set is
axis-aligned, and the phase-aware clipping implementation delegates to the
same phase-conditioned projection logic. SNAP is therefore retained as an
implemented-governor result rather than as an ablation isolating either task
state or margin tightening.

The result therefore supports the need for \emph{context-conditioned
admissibility} when safe and useful command authority depends on manipulation
phase.


\subsection{CRANK: angle conditioning and task-frame representation vary together}

On CRANK, filter-aware SAC achieves 0.0\% safe completion with the static
restriction and 49.4\% with the task-conditioned governor.

The comparison changes more than one representational factor. The static arm
uses the rotation phase to determine its axial restriction, but its transverse
bounds are fixed in world coordinates using the smaller task-axis authority.
The task-conditioned arm additionally tracks crank angle and expresses the
constraint in the rotating task frame.

Accordingly, the experiment shows that the static representation omits
task-relevant structure, but it does not isolate whether the observed
difference is caused by angle conditioning, the task-frame transform, or their
combination. Nor does the observed training stall prove that a required
tangential command is mathematically excluded at every orientation; it is an
empirical learning outcome under the implemented restriction.


\subsection{PCB and PRY: simpler restrictions can be sufficient after adaptation}

The complementary result is equally important. On PCB, filter-aware SAC reaches
100.0\% safe completion with componentwise clipping and 99.8\% with TRiX.
This Stage~2 result does not show a material task-level advantage for exact
structured projection after policy adaptation. It should not be conflated with
the historical Stage~1 PCB comparison, in which filter form and margin
specification differed simultaneously: the componentwise arm bounded each tilt
axis at the nominal $0.100$~N\,m threshold, whereas the executed projection
used a radius of approximately $0.0871$~N\,m, about $12.9\%$ tighter.
Stage~1 therefore does not isolate set geometry as the cause of the observed
PCB difference.

On PRY, filter-aware SAC reaches 88.5\% safe completion with the static
restriction and 89.1\% with TRiX. Once the policy is exposed to the restriction
during training, it can adapt its proposal distribution to the authority
retained by a simpler governor.

A separate PRY control uses a fixed 15,000-step SAC budget, ten training
seeds and 100 evaluation episodes per seed. Its mean safe-completion rates
are 0.0\% without a restriction, 56.0\% with the static restriction and
59.2\% with TRiX; six of ten seeds achieve at least 50\% completion in each
restricted arm. These are separate fixed-budget results, not the Stage~2
checkpoint-selected means above. The restrictions share the intended
zero-insertion bounds but differ as insertion proceeds. The archive's
provenance note reports an initial volume check; without its underlying sample
record we do not retain a numerical volume estimate. The observed results
support the usefulness of both restrictions in this control, without proving
equivalence or isolating task-dependent geometry as a causal factor.



\subsection{BATTERY exact-arm correction}
The historical filename-prefix matcher pooled \texttt{trix} with
\texttt{trix\_preventive} and, in Stage~2, \texttt{box\_clip} with
\texttt{box\_clip\_preventive}. Thirty aggregate records include another arm,
and 22 repeat episode seed IDs. The exact-arm audit maps 1,020 aggregates to
20,400 test shards, checks every displayed cell and retains the selected
checkpoint. The corrected Stage~1 BATTERY/SAC/TRiX mean is 20.0\%, replacing
59.8\% in the intermediate draft. The matched preventive comparison remains
100\% versus 100\%. Original files and the complete correction ledger are
preserved; checkpoint selection was not rerun.

\section{Representation and prospective generalization studies}
\subsection{Procedural Admissible-Set Benchmark}

To separate general representation behavior from the idiosyncrasies of the six
disassembly environments, we generate three-dimensional admissible sets from
six families:

\[
\{\text{box},\text{ ellipsoid},\text{ polytope},
  \text{ state-scaled},\text{ rotating},\text{ phase-gated}\}.
\]

The generator is frozen as specification v1.3. Separate random streams produce
120 training, 40 validation, and 200 held-out instances. The archived held-out evaluation contains 200 instances.

Each generated instance contains a required action sampled from the interior of
its exact admissible set. This action stands in for task-essential control
authority. Before evaluating the competing representations, instances are
stratified according to whether the implemented context-free axis-aligned box retains
that required action.

This stratification is deliberately structural: it is a calibration of the
criterion, not independent evidence that the criterion discovered its own
groups. The empirical comparison within and across strata evaluates how
clipping, learned affine and nonlinear models, context-free and
context-conditioned oracle approximations, and exact projection retain the
required action while remaining feasible.

The learned models are fitted separately for each evaluated geometry using
3,000 labeled state--action samples from that geometry; the nonlinear model
uses 250 fitting steps. Thus the held-out designation refers to the geometry
bank, not to transfer of a single learned model to unseen geometries. Each
method is checked on 400 sampled proposals per instance. Required-action
retention permits displacement below $0.02(\lVert u_{\rm req}\rVert+10^{-9})$.
The context-free box uses the implemented inscribed-box construction and,
for context-dependent families, the componentwise minimum across 21 sampled
contexts. We make no global maximal-volume or continuous-context certification
claim for that construction.


\subsection{Learned representation failure is not explained by training-set size}

The PCB decomposition evaluates representations of the admissible set without
treating each representation as a complete trained safety algorithm.

On the held-out proposal set, componentwise clipping yields 2.9\% feasible
commands. A learned action-affine representation yields 0.0\%. A learned
nonlinear representation reaches 78.0\% with one correction step and 92.3\%
when iterated, while the per-action analytical oracle and exact structured
projection each reach 100\%.

The action-affine result remains at 0.0\% feasibility as its training set is
increased from 500 to 20,000 samples. Thus the observed failure of this
specific learned affine model is not removed by supplying more samples from
the same training distribution. The result supports a representational
limitation of that model class in this experiment rather than an
insufficient-data explanation.

The learned nonlinear result also provides an important counterexample to a
simple ``learned versus symbolic'' interpretation: once the representation is
sufficiently expressive, the iterated learned correction makes 92.3\% of the held-out proposals
feasible. This is a proposal-feasibility rate, not a measure of set recovery. Exact projection remains different because it is supplied with
the declared admissible set rather than learning an approximation to it.

The archived run uses seed 0, 20,000 fitting samples and 2,000 test
proposals. Iteration increases feasibility from 78.0\% to 92.3\% in this run.
The result does not establish the same improvement across training seeds.


\subsection{Procedural benchmark separates context, approximation, and exact projection}

To test representation independently of the semantics of a named disassembly
task, we evaluated six families of procedurally generated three-dimensional
admissible sets: box, ellipsoid, polytope, state-scaled, rotating, and
phase-gated. The frozen generator produced 120 training, 40 validation, and
200 held-out instances from disjoint seed streams. The learned constraint
models are fitted per evaluated instance, as described in Methods.

Each instance contains a required action sampled from the interior of its exact
admissible set. The held-out instances are partitioned according to whether the
implemented context-free axis-aligned box retains that required action.

This partition requires an explicit qualification. It is a constructed
calibration test: the ``needs structure'' group is defined by the context-free
box excluding the required action. Failure of that same box in this group is
therefore close to definitional and is not presented as independent validation
of the criterion.

The useful empirical information is what the partition does not prescribe:
how alternative representations behave inside each group.

All evaluated arms return feasible commands for all 400 sampled
proposals in each of the 200 instances. This is an empirical check on 80,000
proposals per arm, not a universal feasibility guarantee. All approximate
correction arms also use the implemented inscribed-box bounds; those bounds
contribute to feasibility and can remove required authority. The 2\% retention
tolerance explains why two of the 124 box-excluded actions still count as
retained by clipping.

Three observations follow.

First, the learned affine model retains the required action in 0.0\% of the
box-sufficient group even though an ordinary context-free box succeeds on
100.0\% of those instances. This demonstrates that ``linear'' is not a single
capability class: a single learned affine cost representation is not
equivalent to an explicitly represented bounded box, which generally requires
multiple signed inequalities.

Second, context information helps but does not by itself make an approximate
operator exact. The context-conditioned oracle retains the required action in
36.3\% of the structure-required group and 100.0\% of the box-sufficient
group. This number measures the authority retained by the implemented
per-context approximation; it should not be interpreted as a generic tangent
projection error rate.

Third, exact projection retains the required action in 100\% of both groups.
This does not establish that exact projection is necessary for every robotic
task; the PCB, PRY, and BATTERY controls show otherwise. It establishes the
narrower representational point that when the required authority lies inside
the declared admissible set, exact access to that set avoids the authority loss
introduced by the evaluated approximations.


\subsection{Prospective Bayonet Stress Test}

A separate BAYONET experiment was preregistered to test whether the
representation criterion could make a prospective prediction rather than only
explain the original six tasks. Static and phase-gated variants were frozen
before the learned-policy runs, together with comparator arms and a competence
gate.

The primary confirmatory algorithm was SAC, with PPO treated as a secondary
replication. Policies used a 15,000-step training budget, the same frozen
checkpoint-selection rule, ten training seeds, and 100 held-out episodes.
Before observing the final comparison, the protocol declared that a variant
with no learned arm reaching 50\% completion would be classified as
\emph{uninformative} rather than as confirming or falsifying the criterion.
The outcome of this prospective test is reported in the main manuscript without changing
that gate after the run.


\subsection{The prospective BAYONET test was inconclusive}

A separate bayonet task was preregistered to test the representation criterion
prospectively. The protocol declared in advance that the experiment would be
uninformative if no learned arm reached 50\% completion.

That competence gate was not met. Every arm remained below 50\%, with the
highest mean safe-completion rate across ten training seeds reaching
only 10.0\%. Individual seed results are not bounded by that mean. The prospective test
therefore neither confirms nor falsifies the criterion.

The result is retained because the gate and task were frozen before the final
comparison. The task was not softened after the low-competence outcome was
observed. Reporting this null result is part of the evidence that the revised
criterion was not repeatedly modified until every new experiment agreed with
it.


\section{VLM encoding, records and additional analyses}
\subsection{Controlled Foundation-Model Command Study}
\label{sec:si-vlm-method}

The synthetic ``hallucination injection'' experiment is replaced by a
controlled evaluation of actual vision-language-model outputs on one PCB task.
Bank specification v1.0 records the freeze date 11 August 2026 and identifier
\texttt{b3bb5dac2ef5a8fa}. It contains 91 images from 28 base configurations:
21 configurations each have normal, rotated, occluded and misleading visual
conditions, and seven additional configurations each have one partial view.
The three main strata each contain seven configurations and 28 images.

Each provider run receives the same images and prompt, with a 2,000-token
output limit. The recorded configured aliases are:
\begin{itemize}
\item Anthropic: \texttt{claude-sonnet-4-5};
\item OpenAI: \texttt{gpt-4o};
\item Google: \texttt{gemini-flash-latest}.
\end{itemize}
These strings are aliases, rather than pinned snapshot identifiers
\cite{ref36,ref37,ref38}. We use Claude Sonnet, GPT-4o and Gemini as labels
for the runs configured with these aliases. The client permits fallback within
provider pools and writes the configured alias even if a fallback succeeds.
All 273 raw outputs and parsed commands are retained; successful backend IDs,
per-call access times and retry-attempt histories are unavailable in the
recovered archive. Earlier run notes report four Gemini API timeouts that
were retried. The final Gemini file has 91 successful, uniquely identified
response records and no error rows, but the affected images and successful
variants cannot be identified from it. We neither infer that a variant switch
occurred nor assign an unrecorded snapshot to a trial. The accompanying trial
ledger retains each recorded alias and marks unavailable backend information
explicitly. The bank freeze date is not an API access date.

\paragraph{Visual tilt scaling and margin strata.}
The original bank generator applies a numerical display scale:
it stores a display angle $\phi$ and a normalized parameter
$t=\texttt{tilt\_norm}$. For the 21 configurations in the three main strata,
before rounding the saved values,
\[
b=\texttt{TAU\_ROBUST}(1-\texttt{INTERIOR}),\qquad
m=1-|t|/b,\qquad \phi=0.9t/b.
\]
Here $b\simeq0.174174$ is the normalized robust tilt-command bound and $m$
is the generator's relative margin. Replay instead restores the mechanical
curvature angle using
\[
\theta_x=tS_\tau/K_{\rm bend}=0.25t,\qquad \theta_y=0.
\]
Thus the displayed angle is approximately $20.669\theta_x$ for the main
strata. The seven partial configurations use $t=\phi/0.9$, giving
$\phi=3.6\theta_x$; these have no margin-stratum assignment. For example,
\texttt{s00\_normal.png} stores $\phi=0.3248$ rad and $t=0.0629$, whereas
replay restores $\theta_x=0.015725$ rad. Both use the recorded lift of
0.00797 m. The formulas precede rounding of the stored parameters.

The displayed tilt is a visibility-scaled cue, not a depiction of a physically
realisable intact-board state under the benchmark's bending model. In the
saved near-boundary stratum, $|\theta_x|=0.0358$--$0.042525$ rad is displayed
as $|\phi|=42.4^\circ$--$50.4^\circ$, whereas the model's fracture threshold
is $0.075$ rad ($4.30^\circ$). Interpreting those display angles as mechanical
curvature would therefore exceed the fracture threshold.

Within the main strata this positive scaling preserves tilt sign and the
ordering of tilt magnitude and generator margin; the stored values retain
that ordering. It does not preserve the numerical physical angle or make
apparent image distance to a boundary a physical safety margin. The partial
views use a different scale: the same mechanical tilt has an approximately
5.74-fold larger display angle in a main-stratum image. Margin and visual-tilt
comparisons use only the 84 main-stratum images; the seven partial views
are reported separately. Byte-identical
re-rendering from saved display parameters tests rendering reproducibility;
it cannot establish equality of displayed and mechanical tilt. The VLM bank
is separate from the six manuscript workspace illustrations.

The frozen parser maps outputs to \texttt{LIFT}, \texttt{TILT\_X},
\texttt{TILT\_Y}, \texttt{PRESS}, \texttt{HOLD}, or \texttt{ABORT}. Refusal and
ungroundable output are recorded separately. A grounded command is classified
as admissible or inadmissible by comparison with the task projector. The
archive calls the admissible category ``executable''; both admissible and
inadmissible grounded commands can be replayed. It contains no separate
human annotation of semantic correctness.

Each grounded command is held for up to 40 simulator steps in both the
unfiltered and governed arms from the same restored state and seed.
The measured endpoint is an episode-level \emph{constraint-violation case}:
at least one violation during the replay. A \emph{prevented
constraint-violation case} requires a violation in the unfiltered replay and
none in its governed counterpart. We compute this directly from the recorded
violation counts. The historical \texttt{projection\_prevented\_harm} field
combines violations with destructive completion; destructive completion is
zero in every VLM replay, so that field coincides with our violation endpoint
in these records. We do not label it a damage or fracture count. A changed
command alone receives no credit. Refusals remain in the all-image
denominator; replay outcomes use the grounded-command denominator.
This is a single-proposal study, not an autonomous VLM agent loop.


\subsection{Complete outcome accounting}

All 273 decisions are accounted for: 16 refusals, 219 admissible commands and
38 inadmissible commands. There are no ungroundable outputs. The grounded
denominator is $219+38=257$, also equal to $273-16$. Each provider archive
contains one complete record for every bank image. Gemini's 91 records
comprise 65 admissible and 26 inadmissible commands.

The inadmissible counts are 3/91, 9/91 and 26/91 across all inputs for Claude
Sonnet, GPT-4o and Gemini. Among grounded responses they are 3/91, 9/75 and
26/91. The three inadmissible Claude Sonnet commands produce no unfiltered
violation cases and receive no prevention credit. All nine inadmissible
GPT-4o commands and 22 of the 26 inadmissible Gemini commands produce
violations without governance; their governed counterparts produce none.

Across all 257 grounded command pairs, TRiX prevents all 31 observed
constraint-violation cases and introduces no new violation case. Each arm
is evaluated for 40 steps; all replays reach that horizon without task
completion. Both arms record zero destructive completions and zero mechanical
failures. The demonstrated outcome is prevention of constraint violations
during these command executions; damage prevention is not the measured
endpoint.

\paragraph{A recorded command and its paired outcome.}
For \texttt{s06\_occluded.png}, the GPT-4o run returns
\texttt{\{"action":"LIFT","magnitude":0.8\}}. The fixed grounder maps this
to the normalized command $(0,0,0.8)$. The unfiltered replay records
violations on 40 of 40 steps; the governed replay records zero of 40.
These values are read directly from the same trial's stored arm counts.
For comparison, Claude Sonnet's \texttt{LIFT} at magnitude 0.6 on
\texttt{s00\_misleading.png} is inadmissible but produces zero recorded
violations in either arm. The outcome analysis therefore distinguishes a
command correction from an observed prevention benefit.

\subsection{Inadmissible image sets differ across provider runs}

Thirty-five of the 91 images elicit an inadmissible command in at least one
run, and none do so in all three. Of those 35 images, 23 are unique to the
Gemini run, eight to the GPT-4o run, and one to the Claude Sonnet run; three occur
in a pair of failure sets. These are image-level overlaps, not counts of
independent physical configurations.

The three Claude Sonnet inadmissible images and the nine GPT-4o inadmissible
images have an empty intersection, also when grouped by base-state ID.
Holding those recorded classifications fixed, no possible Gemini failure set
can create a three-way overlap. The absence of a shared failure across all
three runs therefore does not depend on identifying the Gemini retries.

As a sensitivity check, changing the inadmissibility labels of at most four
Gemini responses would place its count between 22 and 30 of 91, still above
the fixed GPT-4o and Claude Sonnet counts of nine and three. The observed
Gemini count remains 26. This is a conditional four-response change bound:
the four historically reported timeouts do not establish that only four
decisions could have used another backend. Successful backend IDs were not
logged, and the client permits fallback outside those timeout events.

The shared bank therefore elicits different inadmissible proposal patterns
across the evaluated runs. The counts characterize these observed responses;
the model-version provenance and repeated-configuration design are specified
in Methods.

\subsection{Proposal patterns differ across ordered margin strata}

Using only the 84 main-stratum images, across interior, mid and near-boundary
generator strata, the GPT-4o run has
1/28, 4/28 and 4/28 inadmissible outputs, while the Gemini run has 10/28,
10/28 and 5/28. Each denominator comprises four views of seven configurations.
The Claude Sonnet run has 3/28 in the interior stratum and none in the other two.
Separately, the seven partial-view images contain one inadmissible Gemini
output; none enters a margin-stratum or visual-tilt comparison.

The common positive tilt scaling preserves the ordering of the three main
generator strata. The counts describe responses to that encoding and do not
establish a common monotonic error trend across runs. Without an unscaled
image control, the contribution of visual scaling cannot be separated from
differences between model runs. The margin is the generator's normalized
quantity; it is not an estimate of a safety boundary perceived by a model,
and its numerical value must not be read from the exaggerated display angle.
Partial views are reported separately and repeated views share a base configuration.


\section{Physical platform and trial records}
\subsection{Hardware Platform}

The physical platform is a Seeed reBot Arm B601-RS with RobStride
actuators and gripper, powered from a 48-V supply and commanded over
1-Mbit/s CAN. Joints~1--3 use RS-06 actuators and Joints~4--7 use RS-00
actuators. The existing MIT-style joint controller operates at approximately
200~Hz. The final grasp implementation is frozen at commit
\texttt{d296e6e} and tag
\path{trix-hardware-soft-grasp-success-20260828}.

The hardware execution path preserves the separation between proposal and
command authority. A manipulation action is represented as a symbolic
\texttt{Proposal}; \texttt{TrixProjector} returns an
\texttt{ALLOW}, \texttt{PROJECT}, or \texttt{REJECT} decision;
\texttt{TrixExecutionBridge} converts an approved decision to an
executor-facing command; and \texttt{TrixPhysical\-Target\-Adapter} maps the
approved command to a physical target relative to the joint configuration
captured at trial start. The implementation uses \texttt{ALLOW} when a
proposal is approved without correction.

Joint~1 is enforced as a hard physical invariant. A proposal that explicitly
requests Joint~1 motion is rejected, Joint~1 is excluded from the bridge's
supported command joints, and the physical adapter restores the captured
Joint~1 value before execution.

The final grasp sequence uses J3 model-based gravity feed-forward with
\(\alpha=0.25\). The high-level sequence is governed symbolically, while the
hardware executor contains two disclosed grasp calibrations for the specific
gripper and object: a \(+5^\circ\) Joint~2 grasp-ready positioning offset after
the deep-hover primitive, and a mapping from symbolic gripper state to the
calibrated Joint~7 open and grasp positions. These mappings implement an
approved physical primitive; they are not autonomous grasp synthesis.

For each formal confirmation trial, the evidence package preserves the console
log, passive timestamped CAN traffic, CAN state before and after execution,
source and configuration copies, process exit status, SHA256 checksums, and
continuous video. No independent force/torque sensor is used in this hardware
experiment.


\subsection{Recorded interventions and confirmation trials}

The physical evaluation first tests the central execution-authority claim:
whether an inadmissible upstream request can be prevented from reaching the
actuator interface or modified before physical execution. In the archived
B601-RS intervention experiment, a request for the invalid transition
\texttt{START\_SAFE} to \texttt{LOW\_HOVER} was \texttt{REJECT}ed and
produced no physical target. A proposal requesting \(+50^\circ\) motion of
Joint~1 was hard-rejected and likewise produced no target. In contrast, an
excessive Joint~2 proposal of \(+50^\circ\) was \texttt{PROJECT}ed to
\(+18^\circ\), and only the projected \(+18^\circ\) target was sent to and
executed by the physical robot. The subsequent \texttt{RETURN\_SAFE} request
was \texttt{ALLOW}ed, with final Joint~1 drift of \(+0.007^\circ\). The
complete archived intervention package, including controller logs, passive CAN
captures, run-time repository state, and checksums, is preserved at checkpoint
\texttt{633730c}.

We then evaluated the frozen final V4 implementation in three continuous-video
grasp-and-return trials (\mainref{fig:b601-hardware}). Each trial validated the symbolic sequence before
motion and executed ten TRiX-governed decisions spanning gripper opening,
approach, preshape, low and deep hover, engagement, retraction, and return.
The governed portion of the three trials therefore contained 30 physical
TRiX decisions, all of which were \texttt{ALLOW}. The disclosed grasp-ready
calibration adds the deterministic Joint~2 positioning offset and its inverse
around engagement without changing the frozen symbolic decision sequence.

All three video-backed trials completed with the object retained through the
return, terminated in \texttt{START\_SAFE} with the gripper closed, and exited
with process status zero. All recorded console, CAN, configuration, source, and
metadata files passed their stored SHA256 checks.

The intervention and manipulation experiments test complementary properties.
The former demonstrates that TRiX can suppress or modify a proposed command
before physical actuation. The latter demonstrates that the frozen final
execution architecture can repeatedly carry a useful multi-step manipulation
sequence through the same command boundary. The hardware experiments do not
independently validate the modeled force or wrench limits used in the
simulation studies.


\section{Reactive-governance failure mechanisms}
\subsection{Thermal latency: a current command cannot remove accumulated state}

BATTERY v2 explicitly models latent internal-short dynamics that can
continue generating heat after external force is removed. Its acceptance
test applies a damaging command and then sets the command to zero for 2,000
steps, checking that heating continues. This is a property of the declared
model and its implementation test, not independent thermal validation.
We omit precise trajectory temperatures because their supporting trace was
not recovered in the revision archive.

Once this internal state has been created, a governor acting only on the
current external command cannot remove the energy already represented by the
model. This does not mean that preventive runtime intervention is ineffective;
it means that the intervention must occur before the latent failure state is
created.

The matched-specification experiment demonstrates that distinction. When both
the componentwise preventive arm and TRiX enforce the same 15-N preventive
threshold, both reach 100\% safe completion. The earlier apparent difference
between filter forms was caused by comparing different physical thresholds,
not by an unavoidable advantage of one projection operator.


\subsection{Sequential constraints: projection cannot invent a missing prerequisite}

SNAP exposes a different limitation. Safe extraction requires latch deflection
before pulling. A reactive governor can suppress a pull command that is
inadmissible in the current latch state, but suppressing that command does not
create the preparatory deflection action required for progress.

This distinction separates command admissibility from task planning. Runtime
projection can enforce the declared action set at a given state; it cannot, by
itself, synthesize a missing action sequence. Addressing that failure mode
requires an upstream planner, temporal specification, or other mechanism that
creates the required precondition.


\subsection{Probabilistic tightening can eliminate command authority}

CRANK illustrates a failure caused not by the nominal physical constraint but
by the uncertainty allowance applied to it.

For the axial family, the modeled force-noise standard deviation is 1.235 N
and the nominal limit is 5.00 N. The largest feasible Gaussian multiplier is
therefore approximately

\[
z_{\max}=\frac{5.00}{1.235}\approx4.05.
\]

The declared episode-level allowance requires $z=4.488$. The tightened limit
therefore lies below zero, eliminating positive command authority for that
constraint family.

The appropriate conclusion is not to relax the noise model until the
experiment works. The declared tightened command family is infeasible under these
assumptions. Accordingly, the nominal 5-N CRANK configuration is
excluded from enforcement-guarantee claims; its separate representation study
does not require this probabilistic margin and is interpreted on that narrower
basis.
